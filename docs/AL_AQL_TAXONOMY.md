# مفاتيح al_aql العامة

هذه الطبقة تنفذ فكرة المفاتيح أو الخانات العامة التي تعمل كفئات مجردة داخل عقل مرنان.

بدل أن نكرر مع كل كيان أنه `حيوان` أو `حي` أو `جماد`، نعرّف ذلك مرة في شجرة عامة، ثم نربط الكيان بالمفتاح المناسب.

## المسار

```text
src/physics/al_aql/taxonomy.jl
```

هذا الملف يحتوي منطق القراءة والتطبيق فقط.

أما قاعدة البيانات نفسها ففي:

```text
data/al_aql_taxonomy.json
```

وتُحمّل تلقائياً داخل:

```text
SimulationSpace()
```

كل فضاء محاكاة جديد يحتوي الآن على:

```julia
space.taxonomy
```

## الفكرة

المفتاح العام يحمل:

- اسماً.
- آباء أو مفاتيح أعلى.
- صفات عامة.
- خصائص عددية أولية.
- أعضاء معروفين يمكن تصنيفهم تلقائياً.

مثلاً:

```text
شيء
  ذو_روح
    حي
      حيوان
        مفترس
        آكل_عشب
      نبات
      عاقل
  غير_ذي_روح
    جماد
    مادة
```

إذا قلنا إن `أسد` هو `مفترس`، فهو يفهم أيضاً أنه:

```text
مفترس -> حيوان -> حي -> ذو_روح -> شيء
```

وبذلك يرث صفات عامة مثل:

```text
alive = true
has_body = true
needs_food = true
diet = لحم
```

## واجهات الاستخدام

```julia
space = SimulationSpace()

lion = Thing("أسد"; kind="حيوان")
register_entity!(space, lion; classes=["مفترس"])

is_a(space, "أسد", "حيوان")
assigned_classes(space, "أسد")
explain_classification(space.taxonomy, lion)
```

تحميل قاعدة من ملف:

```julia
tax = load_taxonomy("data/al_aql_taxonomy.json")
```

حفظ قاعدة بعد تعديلها:

```julia
save_taxonomy(space.taxonomy, "data/al_aql_taxonomy.json")
```

ويمكن أيضاً تعديل التصنيف من لغة ADL نفسها:

```adl
مفتاح صياد < إنسان { غذاء: سمك, أعضاء: الصياد }
تصنيف خالد : صياد
فارس : صياد { مهارة: صيد, طاقة: 0.6 }
```

هذه الصيغ تعدل `space.taxonomy` أثناء التشغيل. حفظها إلى ملف يتم عبر `save_taxonomy`.

إضافة مفتاح جديد:

```julia
register_class!(space, "آلة"; parent="جماد",
    attributes=Dict{String,Any}("programmable" => true))

computer = Thing("حاسوب")
register_entity!(space, computer)
assign_class!(space, "حاسوب", "آلة")
```

النتيجة أن `حاسوب` يرث من:

```text
آلة -> جماد -> غير_ذي_روح -> شيء
```

## الحذر المقصود

التصنيف لا يمسح الصفات الخاصة للكيان.

إذا كان للكيان صفة خاصة، تبقى هي الأقوى من الصفة العامة. هذا مهم لأن `أسد` قد يكون له تعريف خاص في قصة أو سياق معين.

كذلك، الخصائص العددية العامة تطبق بحذر على `Thing` العام فقط، حتى لا تغيّر سلوك الكلاسات الفيزيائية القديمة مثل `Lion` و`Gazelle` التي تعتمد عليها اختبارات المحاكاة.

## لماذا ملف بيانات؟

المفاتيح العامة وأعضاؤها ستكبر جداً مع الزمن، لذلك لا يجب أن تعيش داخل الكود.

الكود يجب أن يظل مسؤولاً عن:

- تحميل القاعدة.
- ربط الكيانات بالمفاتيح.
- تطبيق الوراثة.
- الإجابة عن `is_a`.

أما المعرفة نفسها، مثل أن `أسد` عضو في `مفترس` أو أن `حاسوب` عضو في `آلة`، فمكانها قاعدة البيانات.

حالياً الصيغة JSON لأنها بسيطة وموجودة في المشروع. إذا كبرت القاعدة إلى مئات الآلاف أو ملايين العناصر، فالخطوة الطبيعية بعدها هي تقسيمها إلى ملفات متعددة أو نقلها إلى قاعدة بيانات مفهرسة.

## علاقتها بالتحليل العربي

طبقة التحليل العربي تستطيع استخراج أسماء وعلاقات من النص.

طبقة المفاتيح العامة تعطي هذه الأسماء مكاناً في خريطة مفهومية:

```text
اسم مستخرج -> كيان -> مفتاح عام -> صفات موروثة -> قابلية للفعل والتأثر
```

هذا هو الجسر العملي بين الفهم اللغوي والفهم البرمجي داخل مرنان.

## التصنيف من النص

صار `train_from_text!` يلتقط الفئات العامة من الجمل البسيطة.

مثال:

```julia
space = SimulationSpace()

train_from_text!(space, """
الأسد حيوان مفترس قوي.
الحاسوب آلة مفيدة.
الوردة نبات جميل.
""")
```

بعد التدريب:

```julia
is_a(space, "الأسد", "مفترس")   # true
is_a(space, "الحاسوب", "جماد") # true
is_a(space, "الوردة", "نبات")  # true
```

أي أن النص لم يعد يضيف صفات حرة فقط، بل يضع الكيانات داخل الخريطة المفهومية العامة.
