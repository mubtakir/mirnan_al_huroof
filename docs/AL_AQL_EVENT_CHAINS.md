# سلاسل الأحداث المركبة في al_aql

هذه الطبقة تمثل الحالة التي لا تكون فيها الفكرة حدثا واحدا فقط، بل حدثا يفتح وراءه أحداثا لاحقة.

الصورة العامة:

```text
أشياء + حدث أول -> نتيجة 1 -> حدث لاحق -> نتيجة 2 -> حدث لاحق آخر
```

مثال لغوي:

```text
خالد ضرب أحمد فهرب أحمد وسقط الكتاب
```

يمثل داخل `al_aql` كسلسلة:

```text
خالد ضرب أحمد
بعده: أحمد هرب من خالد
بعده: الكتاب سقط على الأرض
```

## الفرق بين العملية والسلسلة

`ProcessConcept` يستعمل عندما نعطي اسما لعملية أو معنى مجرد، مثل الكرم والعدل والجود.

`EventChain` يستعمل عندما نريد وصف توالي وقائع بعد حدث ابتدائي، مثل:

- الضرب ثم الهروب ثم سقوط شيء.
- السلام ثم الرد.
- تقريب شحنتين ثم التنافر ثم ازدياد المسافة.

## الصيغة في ADL

```adl
سلسلة ضرب_ثم_نتائج {
  مصدر: إنسان,
  فعل: ضرب,
  هدف: إنسان,
  ثقة: 0.9;
  خطوة: target هرب source -> هروب_المضروب;
  خطوة: الكتاب سقط الأرض -> سقوط_تابع
}
```

المعاني:

- `مصدر`: فئة الفاعل الأول.
- `فعل`: الحدث الابتدائي الذي يشغل السلسلة.
- `هدف`: فئة الطرف الثاني.
- `ثقة`: درجة ترجيح السلسلة.
- `خطوة`: حدث لاحق في السلسلة.

داخل الخطوة يمكن استعمال:

- `source`: الفاعل الأصلي.
- `target`: الهدف الأصلي.
- اسم صريح مثل `الكتاب` أو `الأرض`.

مثال:

```adl
خطوة: target هرب source -> هروب_المضروب
```

معناه: الهدف الأصلي، أي أحمد في المثال، قام بفعل `هرب` من المصدر الأصلي، أي خالد.

## التشغيل برمجيا

```julia
space = SimulationSpace()

compile_adl!(space, """
مفتاح إنسان_اختبار < إنسان { }
خالد : إنسان_اختبار { }
أحمد : إنسان_اختبار { }
سلسلة ضرب_ثم_نتائج { مصدر: إنسان_اختبار, فعل: ضرب, هدف: إنسان_اختبار, ثقة: 0.9; خطوة: target هرب source -> هروب_المضروب; خطوة: الكتاب سقط الأرض -> سقوط_تابع }
""")

frames = run_event_chain!(space, "ضرب_ثم_نتائج", "خالد", "أحمد")
```

الناتج يكون إطارات سببية `CausalFrame`، ومع كل خطوة تسجل علاقة زمنية في:

```julia
space.temporal_relations
```

بهذا يستطيع مرنان أن يحتفظ بأن الحدث الثاني وقع بعد الأول، والثالث بعد الثاني، بدل أن يرى الأحداث نقاطا منفصلة.

## الحالة الحالية

السلاسل الآن تسجل:

- الحدث الابتدائي الذي تنطلق منه السلسلة.
- خطوات لاحقة مرتبة.
- درجة ثقة عامة.
- علاقات زمنية من نوع `بعد`.
- إنشاء الكيانات الصريحة في الخطوات إذا لم تكن موجودة.

الخطوة اللاحقة المناسبة هي ربط السلاسل تلقائيا مع `infer_event!` أو `evaluate_idea!` عندما نقرر أن التشغيل التلقائي مطلوب، أما الآن فالتشغيل صريح عبر `run_event_chain!`.
