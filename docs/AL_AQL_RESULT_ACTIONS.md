# تطبيق فعل النتيجة في al_aql

كان `CausalTemplate` يسجل النتيجة السببية وصفيا. الآن إذا احتوى النمط على `فعل_النتيجة` وكان هذا الفعل معرفا كفعل ديناميكي، فإن `infer_event!` يطبق هذا الفعل فعليا على كيان النتيجة.

## مثال: الملح ودرجة غليان الماء

```adl
مفتاح مادة < شيء { }
ماء : مادة { boiling_point: 100.0 }
ملح : مادة { quantity: 1.0 }

رفع_الغليان : فعل { الهدف: boiling_point, مقياس: 2.0 }
علاقة boiling_point خاصية_لـ ماء

نمط مشروط اضافة_ملح_ترفع_الغليان {
  مجال: كيمياء,
  مصدر: مادة,
  فعل: اضافة,
  هدف: مادة,
  شرط: source.quantity > 0,
  فاعل_النتيجة: الهدف,
  فعل_النتيجة: رفع_الغليان,
  نتيجة: زيادة_درجة_الغليان,
  ثقة: 0.9
}
```

عند تنفيذ:

```julia
infer_event!(space, "ملح", "اضافة", "ماء")
```

يرتب النظام المعنى هكذا:

```text
الأشياء: ملح، ماء، boiling_point
العلاقة: boiling_point خاصية_لـ ماء
الحدث: اضافة ملح إلى ماء
الشرط: source.quantity > 0
النتيجة الوصفية: زيادة_درجة_الغليان
فعل النتيجة التنفيذي: رفع_الغليان على ماء
```

ثم يغير قيمة `boiling_point` في كيان `ماء`.

## قاعدة العمل

- إذا لم يكن `فعل_النتيجة` معرفا، يبقى النمط وصفيا كما كان.
- إذا كان `فعل_النتيجة` معرفا في `space.dynamic_verbs`، يطبق بعد تسجيل الإطار السببي.
- الخصائص الحرة مثل `boiling_point` تحفظ كسمات عددية ولا تحصر بين 0 و1.
- الخصائص الفيزيائية المعروفة مثل `fear` و`energy` تبقى مطبعة داخل متجه الخصائص.
