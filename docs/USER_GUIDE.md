## 2. ماذا يحدث عند بدء الخادم؟

عند تشغيل `run_server.bat`، يمر الخادم بـ **3 مراحل إعداد** قبل قبول أي طلبات:

```
جاري تحميل النموذج المدرب...
  → معجم: 1223 كلمة
✓ تم تحميل النموذج بنجاح.

⟳ [1/3] JIT warm-up — تجميع محرك التوليد الفيزيائي...
  ✓ JIT اكتمل في ~4s

⟳ [2/3] تسخين cache المتجهات الطورية (1223 كلمة)...
  ✓ تم تسخين 1223 كلمة في ~1s

⟳ [3/3] اختبار السرعة بعد التسخين...
  'كلمة' → 'نتيجة...' (~3-5s)

==================================================
  ✓ النموذج جاهز للاستخدام!
==================================================
  خادم مرنان V8 يعمل الآن على: http://127.0.0.1:8000
```

### شرح المراحل

| المرحلة | ما يفعله | لماذا ضروري |
|---------|----------|-------------|
| **[1/3] JIT warm-up** | Julia تُجمّع كود 75+ محرك فيزيائي | بدونه، أول طلب مستخدم يأخذ 30-60 ثانية |
| **[2/3] تسخين cache** | حساب المتجهات الطورية (10,000 بُعد) لكل كلمة مسبقاً | يُخفّض زمن الاستجابة من 30s إلى 3-8s |
| **[3/3] اختبار السرعة** | توليد تجريبي للتأكد من صحة النظام | يُثبت أن النموذج جاهز |

> [!NOTE]
> الإعداد الكلي يأخذ **30-90 ثانية** حسب سرعة الجهاز. هذا طبيعي وحدث مرة واحدة فقط عند كل تشغيل.

## 3. توقعات الأداء والزمن

### زمن الاستجابة بعد التسخين

| حجم الكوربس | زمن الاستجابة المتوقع |
|-------------|----------------------|
| صغير (< 5,000 كلمة) | 2–5 ثانية |
| متوسط (5,000–50,000 كلمة) | 5–15 ثانية |
| كبير (> 50,000 كلمة) | 10–30 ثانية |

### لماذا مرنان أبطأ من النماذج الإحصائية؟

مرنان **نموذج فيزيائي** وليس إحصائياً. في كل استجابة يُنفّذ:

- محاكاة **مذبذبات كوراموتو** (Kuramoto oscillators)
- حساب **الجاذبية الدلالية** N-body في فضاء 10,000 بُعد
- **75+ محرك فيزيائي** متوازٍ
- **جبر كليفورد** الهندسي للعلاقات الطورية

هذه الدقة الفيزيائية هي سبب استحالة مقارنته بنموذج إحصائي. الثمن هو الزمن.

### ما الذي يُسرّع الاستجابة؟

- الـ `pv_cache` يحتفظ بالمتجهات الطورية المحسوبة — الطلبات المتكررة لنفس الكلمات أسرع
- الـ `pv_cache` **لا يُحفظ على القرص** — يُعاد بناؤه عند كل تشغيل (لهذا الـ warm-up ضروري)

### مستويات تقسيم النص (Granularity)

> [!IMPORTANT]
> **اختيار مستوى التقسيم الصحيح ضروري لجودة الاقترانات.**
> الاختيار الخاطئ يخلق ارتباطات وهمية بين كلمات لا علاقة منطقية بينها.

يمكن التحكم في كيفية تقسيم كل ملف إلى وثائق مستقلة:

| المستوى | الأمر | السلوك | متى تستخدمه |
|---------|-------|--------|-------------|
| `:paragraph` | الافتراضي أو `--paragraph` | كل فقرة (مفصولة بسطر فارغ) = وثيقة | قصص بمشاهد منفصلة، كتب، موسوعات، حوارات، كوربس مرنان المنسق |
| `:document` | `--document` | كل ملف = وثيقة واحدة — النص كله متصل | نصوص سردية متصلة، شرح برمجي، مقال طويل |
| `:line` | `--line` | كل سطر = وثيقة | أمثال، أحاديث، أوامر، بيانات مهيكلة |

**شرح مفصل مع أمثلة وحالات استخدام**: راجع [دليل التدريب — القسم 3: مستويات التقسيم](TRAINING_GUIDE.md#3-مستويات-التقسيم-granularity).

**مثال سريع:**
```bash
# الوضع الافتراضي: كل فقرة = وثيقة مستقلة:
julia --project=. train.jl

# أو صراحة:
julia --project=. train.jl --paragraph

# للشرح البرمجي المتصل:
julia --project=. train.jl --document

# للأمثال والأحاديث (كل سطر قائم بذاته):
julia --project=. train.jl --line
```

### كيفية صياغة وكتابة النصوص التدريبية
لكي يتعلم مِرنان العلاقات اللغوية والبرمجية بدقة ويتجنب الضوضاء الدلالية، يرجى كتابة النصوص التدريبية وفق القواعد التالية:

#### 1. صياغة نصوص اللغة الطبيعية (العربية/الإنجليزية):
- **للنصوص السردية والمقالات المترابطة:** اكتب الجمل بشكل متصل لضمان اقتران نهايات الجمل ببعضها.
- **للمواضيع أو المشاهد المنفصلة (مثل الحوارات أو مقالات الموسوعات المتنوعة):** افصل بين كل فكرة أو حوار والآخر بـ **سطر فارغ**؛ هذا يمنع اقتران نهاية الفكرة الأولى ببداية الفكرة الثانية بالخطأ عند التدريب على مستوى الفقرات (`--paragraph`).
- **للحكم والأمثال:** ضع كل حكمة في سطر مستقل لتدريبها على مستوى الأسطر (`--line`).

#### 2. صياغة الأكواد البرمجية (هام جداً):
- **قاعدة فصل الكود:** يجب إحاطة الأكواد البرمجية بعلامات الاقتباس الثلاثية ` ``` ` (مثل ` ```python ` أو ` ```julia `).
- يقوم مِرنان أثناء التدريب باستخراج هذه الكتل تلقائياً وبناء مصفوفة اقتران برمجي مستقلة `K_code` حتى لا تتداخل الكلمات والمفاهيم البرمجية (مثل `def` أو `return` أو الرموز الرياضية) مع مفردات المعجم العربي.
- الشروحات العربية للكود تكتب خارج هذه العلامات الثلاثية بشكل طبيعي.

**مثال على الصياغة الصحيحة للمزج بين الشرح والكود:**
```text
لتعريف دالة لحساب المجموع في بايثون نستخدم الكلمة المفتاحية def:

```python
def add_numbers(a, b):
    return a + b
```

نقوم بعد ذلك باستدعاء الدالة وتمرير القيم لها.
```

```

```

## 6. ضبط عوامل التحكم بقوة الجاذبية (Gravity Controls)

يمكنك التحكم بدقة التوليد وتماسك الجمل والكلمات عبر تعديل قيم الجاذبية في ملف الإعدادات `config.yaml`:

```yaml
gravity:
  semantic_factor: 0.3       # معامل قوة الجاذبية الطورية الدلالية
  positional_factor: 2.5     # معامل قوة الجاذبية الموضعية النحوية
```

* **معامل الجاذبية الدلالية (`semantic_factor`)**: يتحكم بمدى ترابط الكلمات بناءً على معناها وسياقها العام في فضاء الأطوار (مما يحافظ على وحدة الموضوع ويمنع الانفلات الدلالي). 
  * **💡 ميزة تجريبية (الجاذبية المعكوسة)**: عند تعيين هذا المعامل بقيمة سالبة (مثلاً `-0.2`)، يتحول حقل الجذب الطوري إلى **قوة تنافر دلالية**، مما يدفع المحرك لتجنب التكرار وتفادي الجمود اللغوي، مما يتيح توليداً حراً وشاعرياً للغاية.
* **معامل الجاذبية الموضعية (`positional_factor`)**: يتحكم بقوة الترابط النحوي والانتقالي بين الكلمات المتجاورة في الجملة (الترابط النحوي القريب).

### 🛡️ التداخل الطوري الهدّام (Destructive Phase Interference)
لمنع تسرب الكلمات البرمجية أو سجلات النظام المتكررة (مثل *"الملف بنجاح"* أو *"إغلاق النافذة"*) إلى المحادثات الحوارية الطبيعية، يدعم مرنان V8 حظراً فيزيائياً عبر عكس متجه طور الكلمة ($v' = -v$).

يتم ضبط ذلك في ملف الإعدادات `config.yaml`:
```yaml
destructive_phase:
  enabled: true                 # تفعيل التداخل الطوري الهدام
  system_words:                 # قائمة بالكلمات النظامية المراد حظرها دلالياً
    - "الملف"
    - "بنجاح"
    - "النافذة"
    - "اغلاق"
```
*يقوم المحرك داخلياً بتطهير حركات التشكيل من الكلمات لضمان الحظر التام بكافة الحركات النحوية.*

## 7. استكشاف الأخطاء وإصلاحها

### ❌ الواجهة عالقة على "يتفاعل فيزيائياً..."

**السبب**: فتحت المتصفح قبل اكتمال الـ warm-up، أو الخادم لم يبدأ.

**الحل**:
1. انتظر رسالة **"✓ النموذج جاهز للاستخدام!"** في نافذة الخادم
2. ثم فقط افتح `http://127.0.0.1:8000`
3. الطلب سيأخذ **3-15 ثانية** وهذا طبيعي

---

### ❌ النموذج لا يُنتج أي نص (نتيجة فارغة)

**السبب الأكثر احتمالاً**: الكلمة التي كتبتها غير موجودة في المعجم.

**الحل**:
- تأكد أن الكلمة موجودة في بيانات التدريب
- أعد التدريب بعد إضافة البيانات الجديدة

**تشخيص**: في نافذة الخادم ستجد:
```
═══ طلب توليد ═══
  المحفز: "كلمتك" | الوضع: standard | أقصى كلمات: 10
  ✓ توليد مكتمل في 0.03s → ""   ← نتيجة فارغة = الكلمة خارج المعجم
```

---

### ❌ رسالة "انتهت مهلة الانتظار (5 دقائق)"

**السبب**: التوليد أخذ أكثر من 5 دقائق.

**الحل**:
1. أعد المحاولة — إذا كان الخادم لم يكمل الـ warm-up بعد، ستعمل المحاولة الثانية
2. إذا تكرر، تحقق من حجم الكوربس — المعاجم الكبيرة جداً (> 500,000 كلمة) تحتاج أجهزة أقوى

---

### ❌ الخادم لا يبدأ أو يتوقف فجأة

**تحقق من**:
```bat
:: تحقق أن Julia مثبتة
"C:\Users\allmy\AppData\Local\Programs\Julia-1.12.6\bin\julia.exe" --version

:: تحقق أن النموذج مدرب
dir model\
```

إذا كان `model\` فارغاً، شغّل `run_train.bat` أولاً.

---

### ❌ زمن الاستجابة بطيء جداً (> 30 ثانية)

**الأسباب والحلول**:

| السبب | الحل |
|-------|------|
| فتحت المتصفح قبل اكتمال warm-up | أغلق وأعد التشغيل وانتظر الرسالة |
| المعجم كبير جداً | طبيعي للكوربس الكبير |
| جهاز محدود الذاكرة (< 4GB) | أغلق البرامج الأخرى |

## 8. ملاحظات فنية عن الطبيعة الفيزيائية للنموذج

### لماذا مرنان ليس نموذجاً إحصائياً

مرنان نموذج **فيزيائي** وليس إحصائياً. في كل استجابة يُنفّذ:

- محاكاة **مذبذبات كوراموتو** (Kuramoto oscillators) في فضاء 10,000 بُعد
- حساب **الجاذبية الدلالية** N-body بين كل أزواج الكلمات
- **75+ محرك فيزيائي** متوازٍ (جبر كليفورد، حقل التدفق السببي، مصفوفة الكثافة الكمومية...)
- **حلقة تغذية راجعة مغلقة**: كل توليد يُقيَّم ← يُعزَّز أو يُضعَف ← النموذج يتحسن ذاتياً

### الطبقات الفيزيائية السبع

مرنان يبني "الفهم" عبر 7 طبقات فيزيائية متراكبة، كل منها مستوحاة من قانون فيزيائي حقيقي:

```
┌──────────────────────────────────────────┐
│ ٧. حلقة التغذية الراجعة المغلقة          │
│    توليد ← تقييم (5 مقاييس) ← تعزيز/إضعاف │
├──────────────────────────────────────────┤
│ ٦. مصفوفة الكثافة الكمومية ρ             │
│    المكافئ الفيزيائي للـ word embedding   │
├──────────────────────────────────────────┤
│ ٥. الموجة الحاملة والمحمولة               │
│    الاسم = موجة حاملة، الفعل = موجة محمولة │
├──────────────────────────────────────────┤
│ ٤. فكرة = أشياء + حدث + نتيجة            │
│    النص يُفهم كأفكار لا ككلمات            │
├──────────────────────────────────────────┤
│ ٣. دوائر الرنين LC                        │
│    كل كلمتين متجاورتين = دائرة رنين كاملة  │
├──────────────────────────────────────────┤
│ ٢. الجاذبية الدلالية                      │
│    F = G·m₁·m₂/r² — كلمات الجملة تتجاذب  │
├──────────────────────────────────────────┤
│ ١. طاقة الكلمة وكتلتها                    │
│    E = hf → m = E/c² (h=c=G=1)           │
└──────────────────────────────────────────┘

للاطلاع على الشرح الكامل لكل طبقة وكيف تعمل معاً:
→ docs/TRAINING_GUIDE.md#4-كيف-يتعلم-مرنان--العمارة-الكاملة
```

### كيف "تُعرِّف" الموجة الحاملة الكلمات

في الجملة، **الاسم هو الموجة الحاملة** و**الأفعال والصفات موجات محمولة** عليها. عبر الكوربس، كل جملة تحوي نفس الاسم تجعل موجاته الحاملة **تتجاذب طورياً** وتجذب محمولاتها:

```
"الملك يحكم الناس"  ←  حامل: الملك، محمولات: [يحكم, الناس]
"للملك سلطة"        ←  حامل: الملك، محمولات: [سلطة]
"المال في جعبة الملك" ← حامل: الملك، محمولات: [مال, جعبة]

← تتراكب في ρ ← تعريف: "من يحكم بلاداً وله سلطة ويملك مالاً"
```

هذا هو **المكافئ الفيزيائي للـ word embedding** — لكنه يُبنى من فيزياء الكلمات لا من إحصاء تردداتها.

### حلقة التغذية الراجعة — التعلم الذاتي

**كل جملة يولّدها مرنان تُقيَّم فيزيائياً وتُغذّي النموذج:**

```
أنت: "العلم نور"
مرنان: "نور الحقيقة"
        │
        ▼ تقييم (5 مقاييس)
  تماسك طوري:     0.71  ✓
  طاقة جاذبية:    0.83  ✓
  استقرار رنين:   0.65  ✓
  رنين الكثافة:   0.58  ✓
  محاذاة الأمر:   0.90  ✓
        │
  الجودة = 0.73  ←  جيد (>0.4)
        │
        ▼ تعزيز
  • تقوية آثار الكلمات (PhaseReinforcer)
  • تقريب المتجهات المتجاورة (PhaseEvolution)
  • زيادة أوزان K_sem (+0.007)
  • إضافة إلى ذاكرة ρ
```

**لمراقبة أداء الحلقة:**
```
> /report
الإنتروبيا=0.12 β=2.1 كلمات=1223
تغذية راجعة: جيد=15 ضعيف=3 تماسك=0.58 نسبة=0.833
```

**كيف تستفيد:** كلما تفاعلت مع مرنان أكثر، تحسّن أكثر. بعد 20-50 جلسة، النموذج "تعلّم" تفضيلاته. لا تحتاج لإعادة تدريب — التعلم مستمر أثناء الاستخدام.

### لماذا يأخذ التدريب وقتاً؟

التدريب يبني **خمس طبقات تعلم** (وليس فقط مصفوفات K):

| المرحلة | ماذا تبني | الزمن التقريبي |
|---------|-----------|---------------|
| 1-3. K_sem, K_syn, K_dialogue | مصفوفات الاقتران من الكوربس | 60% من زمن التدريب |
| 4.1. carrier_coupling! | اقتران الموجة الحاملة (اسم←→فعل) عبر Hilbert transform | 25% |
| 4.2. PhaseEvolution | تطور المتجهات الطورية (تعلم هيبياني عبر الكوربس) | 15% |
| 5. K_code | مصفوفة اقتران منفصلة للكود البرمجي | سريع |

### ملفات النموذج المحفوظة

```
model/
├── vocab.json              ← المعجم (كلمة → معرف)
├── K_sem.dat               ← مصفوفة الاقتران الدلالي
├── K_syn.dat               ← مصفوفة الاقتران النحوي
├── K_dialogue.dat          ← مصفوفة الاقتران الحواري
├── corpus_sentences.dat    ← جمل الكوربس للـ PRNN
├── code_vocab.json         ← مفردات الكود (17 نوع رمز)
└── K_code.dat              ← مصفوفة اقتران الكود
```

### ما الفرق بين مرنان والنماذج الإحصائية؟

| | مرنان (فيزيائي) | GPT/BERT (إحصائي) |
|--|----------------|------------------|
| **أساس التوليد** | معادلات الفيزياء (موجات، جاذبية، رنين) | احتمالات إحصائية |
| **التدريب** | 5 طبقات: K matrices + carrier coupling + phase evolution + K_code | backpropagation على مليارات المعاملات |
| **الذاكرة** | مصفوفة كثافة كمومية ρ (تحديث تراكمي) | متجهات ثابتة (embeddings) |
| **التعلم الذاتي** | حلقة مغلقة: توليد ← تقييم ← تعزيز | لا يوجد (يحتاج fine-tuning) |
| **الزمن** | ثوانٍ إلى دقائق | ميلي ثانية (بعد تدريب ضخم) |
| **التفسير** | كل قرار له تفسير فيزيائي | "صندوق أسود" |
| **المعنى** | رنين طوري حقيقي | تشابه إحصائي |
| **التحسن مع الاستخدام** | ✓ يتحسن ذاتياً عبر الحلقة المغلقة | ✗ ثابت بعد التدريب |

## 9. توليد الكود البرمجي (Code Mode)

### كيف يعمل نمط الكود؟

يمتلك مرنان **مصفوفة اقتران منفصلة للكود** (K_code) تُبنى تلقائياً أثناء التدريب من كتل ` ```...``` ` الموجودة في الكوربس. عند طلب توليد كود، يستخدم مرنان:

1. **قوالب جاهزة** للأنماط الشائعة (دالة، حلقة، شرط، كلاس، استيراد)
2. **البحث الرنيني** في K_code للأنماط غير المغطاة بالقوالب
3. **قيد VALID_NEXT** الصارم لمنع التراكيب النحوية الخاطئة
4. **تغذية راجعة** (code feedback) تعزز الاقترانات الصحيحة وتنافر الخاطئة

### أوضاع التوليد للكود

#### الوضع الصريح: `--mode code`

```bash
# في CLI التفاعلي:
> /mode code
> اكتب دالة فرز

# أو من سطر الأوامر:
julia --project=. cli.jl --mode code "def sort"
```

#### الوضع التلقائي: `auto`

في الوضع `auto`، يكشف مرنان تلقائياً إذا كان الطلب برمجياً من خلال كلمات مفتاحية عربية وإنجليزية:

```
> /mode auto
> اكتب دالة تجمع رقمين     ← يُكشف ككود → يولد def
> كيف حالك                 ← يُكشف كلغة طبيعية → يولد نصاً
```

**الكلمات التي تُفعّل نمط الكود تلقائياً:**

| عربية | إنجليزية |
|-------|----------|
| كود، برنامج، برمجة، دالة، دوال، حلقة، شرط، مصفوفة، متغير | def, class, function, import, return, for, while, if |
| كلاس، صنف، استيراد، تصدير، إرجاع، خطأ، تصحيح | print, code, program, loop, array, debug, syntax |
| خوارزمية، بايثون، جوليا، اكتب، أنشئ، صمم، برمج | algorithm, compile, build, run, error, bug, fix |

### القوالب المدعومة

| النمط | يُستدعى عند وجود | مثال الناتج |
|-------|-----------------|-------------|
| دالة | `دالة`، `function`، `def` | `def my_func():`<br>`    pass` |
| حلقة | `حلقة`، `for`، `while`، `loop` | `for i in range(10):`<br>`    pass` |
| كلاس | `صنف`، `كلاس`، `class` | `class MyClass:`<br>`    pass` |
| شرط | `شرط`، `if`، `condition` | `if x > 0:`<br>`    pass`<br>`else:`<br>`    pass` |
| استيراد | `import`، `from`، `استيراد` | `import math` |
| عام | أي شيء آخر | بحث رنيني في K_code مع VALID_NEXT |

> [!NOTE]
> القوالب تستخرج اسم الدالة/الكلاس من الطلب تلقائياً. مثلاً "اكتب دالة حساب" ← `def حساب():`، و "أنشئ كلاس طالب" ← `class طالب:`.

### التحقق من الصحة النحوية

قبل إرجاع الكود، يتحقق مرنان من:
- وجود بنية برمجية معروفة (`def`، `for`، `=`...)
- خلو الكود من أحرف غير Pythonic (`{`، `}`، `;`)
- تطابق تسلسل الرموز مع قواعد VALID_NEXT

إذا فشل التحقق، يُسجّل الخطأ وتُضعف الاقترانات الخاطئة في K_code (تغذية راجعة طورية).

### ماذا لو لم يُدرَّب على كود؟

إذا لم يحتوي الكوربس على كتل ` ```...``` `، فلن تُبنى K_code. في هذه الحالة:

```bash
> /mode code
> اكتب دالة
  ↳ # [CodeEngine: no code vocab loaded]
    pass
```

الحل: أضف ملفات تدريب تحتوي كوداً داخل ` ``` ` وأعد التدريب. راجع [دليل التدريب — القسم 6](TRAINING_GUIDE.md#6-تدريب-على-البرمجة-والكود).

### مثال كامل

```bash
# 1. التدريب (مرة واحدة)
julia --project=. train.jl

# 2. الدخول التفاعلي
julia --project=. cli.jl -i

# 3. داخل الجلسة
> /mode code
> اكتب دالة تحسب مضروب العدد factorial
  ↳ def factorial(n):
      if n <= 1:
          return 1
      return n * factorial(n - 1)

> /mode auto
> كيف يعمل import في بايثون     ← يكتشف "import" ← نمط كود
  ↳ import math

> السلام عليكم                   ← لا كلمات كود ← نمط قياسي
  ↳ ورحمة الله وبركاته
```

### ملفات النموذج الخاصة بالكود

بعد التدريب، ستجد في مجلد `model/`:

| الملف | المحتوى |
|-------|---------|
| `code_vocab.json` | مفردات الكود — 17 نوع رمز (KEYWORD, IDENTIFIER, OPERATOR...) |
| `K_code.dat` | مصفوفة اقتران الكود — انتقالات الرموز البرمجية |

## 10. التوليد بالانتشار الرنيني (Resonant Mode)

### ما المشكلة التي يحلها؟

في المعاجم الكبيرة (>50,000 كلمة)، نمط `standard` (البحث الشعاعي) بطيء جداً — 30-250 ثانية للجملة الواحدة. السبب: يقيم 400+ مرشح × 40+ محرك فيزيائي لكل كلمة مولَّدة.

### الحل: الانتشار الرنيني

> [!IMPORTANT]
> **فكرة ثورية:** مصفوفة الاقتران K ليست "قاعدة بيانات للبحث" — بل **وسط انتشار موجي**. كل وزن K[i,j] هو قوة اقتران بين مذبذبين. الإثارة تنتشر تلقائياً عبر الشبكة، والكلمات الأكثر رنيناً تنبثق كجواب.

### سرعة مذهلة

| حجم المعجم | `standard` (بحث شعاعي) | `resonant` (انتشار رنيني) | التحسن |
|-----------|----------------------|--------------------------|--------|
| 155K كلمة | 98-252 ثانية | **0.4-1.3 ثانية** | **100-200x** |
| 10K كلمة | 3-8 ثوانٍ | <0.1 ثانية | 30-80x |
| 1K كلمة | <1 ثانية | <0.01 ثانية | فوري |

### كيفية الاستخدام

```bash
# في الوضع التفاعلي:
> /mode resonant
> العلم نور
  ↳ في السلوك الوجود هو فان الفكر ان الي يودي العقل

# من سطر الأوامر:
julia --project=. cli.jl --mode resonant "السلام عليكم"
  ↳ الله عليه صلي علي الي الملاحظه الفكر هو كل المنطق

# الوضع التلقائي (للمعاجم >50K يختار resonant تلقائياً):
> /mode auto
```

### آلية العمل — باختصار

```
كلمات الأمر  ←  تثير مذبذباتها
      │
K × phase  ←  انتشار الموجة عبر 20M اقتران (0.01s)
      │
الكلمات الأكثر إثارة + الأقرب طورياً لحقل الكثافة  ←  الجواب
      │
تغذية راجعة  ←  الكلمة المختارة تصبح مصدر إثارة جديد
```

> [!NOTE]
> لشرح فيزيائي مفصل للانتشار الرنيني والمقارنة مع البحث الإحصائي:
> → [دليل التدريب — القسم 14](TRAINING_GUIDE.md#14-التوليد-بالانتشار-الرنيني-resonant-mode--ثورة-فيزيائية)

### متى تستخدم ماذا؟

| المعجم | النمط التلقائي | ملاحظات |
|--------|---------------|---------|
| < 10K كلمة | `standard` | البحث الشعاعي سريع كفاية |
| 10K-50K | `standard` أو `creative` | كلهما مقبولان |
| > 50K | **`resonant` (تلقائي)** | فرق السرعة هائل |

## 11. الإدراك الدلالي — كيف "يفهم" مرنان

### الفطرة اللغوية الرقمية

مرنان لا يتعلم اللغة من الصفر. لقد زُرعت فيه **فطرة لغوية** رقمية منذ البداية:

- **كل حرف** له 22 بُعداً دلالياً ثابتاً (تركيز، كثافة، حرارة، حركة، صلابة...)
- **الكلمة** = جداء هندسي (جبر كليفورد) لمتجهات حروفها — 255 بُعداً
- **الجملة** = جداء هندسي لمتجهات كلماتها — متجه واحد يلتقط المعنى الكلي
- **الموضوع** = مصفوفة كثافة ρ تتراكم من الجمل — "ذاكرة" الموضوع الجاري

> [!IMPORTANT]
> هذا يعني أن مرنان **يدرك المعاني دلالياً** قبل أن يرى أي نص تدريبي. يمكنه حساب الفرق الدلالي بين كلمتين، وحل التناظرات (ملك:مملكة :: رئيس:؟)، ومعرفة أن "السلام عليكم" و"وعليكم السلام" تنتميان لنفس الموضوع حتى لو اختلفت كلماتهما.

### كيف يمنع هذا الانحراف الموضوعي؟

المشكلة السابقة: "السلام عليكم" ← أول كلمة صحيحة ("ورحمه") ثم ينجرف إلى الفلسفة ("الفكر"، "الوجود"...).

الحل: **الرنين الموضوعي**. كل كلمة مرشحة أثناء التوليد تُفحص:

```
هل تنتمي هذه الكلمة لموضوع التحية؟
  "ورحمه"  ← رنين عالٍ مع TopicDensityMatrix ✓ مقبولة
  "الفكر"  ← رنين منخفض ✗ مرفوضة
```

النتيجة: الجملة تبقى في موضوعها — تحية تبقى تحية، شرح علمي يبقى شرحاً علمياً.

### أين يعمل هذا؟

الإدراك الدلالي مفعّل تلقائياً في نمط `resonant`. لا يحتاج تفعيلاً يدوياً.
